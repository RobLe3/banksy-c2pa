# OpenAI image provenance

This project preserves and extends C2PA history; it is not a general AI-image detector.

## Signals OpenAI may add

OpenAI documents two provenance signals for supported images generated by ChatGPT, Codex, and the OpenAI API:

- **C2PA Content Credentials:** signed metadata that can identify an issuer and describe AI use.
- **SynthID:** a watermark embedded in supported media.

Coverage varies by product, model, export path, file format, and creation date. Editing, conversion, screenshots, or sharing platforms can remove C2PA metadata. A watermark may survive some transformations, but a negative result is not proof that an image was made by a person.

Sources:

- [Provenance signals in OpenAI-generated content](https://help.openai.com/en/articles/8912793-c2pa-in-chatgpt-images)
- [OpenAI Content provenance guide](https://developers.openai.com/api/docs/guides/content-provenance)

## What banksy-c2pa handles

`banksy-c2pa` reads and writes C2PA manifests in PNG and JPEG files. It does not detect, inspect, add, or validate SynthID.

### Unchanged image

Use `attest` when the pixels are unchanged:

```bash
banksy-c2pa inspect image.png
banksy-c2pa attest image.png --published
```

If `image.png` has a valid active C2PA manifest, the tool creates an update manifest. The upstream manifest remains reachable in the resulting history, while the new claim records the configured local signer and its separate editorial or publication action. The output must decode to the same pixels as the input.

### Edited image

Use `derivative` when pixels changed:

```bash
banksy-c2pa derivative \
  --parent openai-original.png \
  --input edited.png \
  --description "Cropped and annotated for publication"
```

The original becomes a `parentOf` ingredient. Its valid embedded C2PA history remains attached to that relationship. The tool requires the edited input to differ from the parent and reports `c2pa.edited` rather than pretending only metadata changed.

### Inspection

`inspect` reports the available C2PA issuer, claim generator, actions, ingredients, validation state, and manifest count. A local update does not replace the meaning of an upstream OpenAI claim; each signer is responsible for its own assertions.

### Transfer

`package` stores the exact signed image bytes in an evidence ZIP with checksums. This is useful when an image-upload route might re-encode the file and remove its C2PA container data.

## Limits

- A missing OpenAI credential does not prove that an image was not generated by OpenAI or another AI system.
- A credential removed before the tool receives a file cannot be reconstructed.
- The tool does not infer a prompt, account, individual creator, copyright owner, or legal right from a provenance signal.
- A locally issued certificate is not automatically trusted by public C2PA verifiers.
- Pixel-preserving C2PA attestation does not validate SynthID, even if the unchanged pixels may still carry it.
- For edited derivatives, the tool makes no claim about whether an upstream watermark survives the edit.

Use provenance as one item of evidence within a broader review, not as a complete history or a truth certificate.
